# Plan + Verify checklist

## Plan

A good plan fits in a short message. If it needs a page, it is not
a plan yet — it is a document.

- Goal: 1 sentence, in the user's words
- Steps: 3-7 concrete outcomes, in order
- Check: what "done" means, and how you will test it
- Out of scope: what you will NOT do

## Verify

- Re-open every file you created and read it back.
- Click / open every link you send. A link that 404s is a failure.
- Check dates, prices, versions, and names against the source
  you got them from — not from memory.
- Run the thing, if it can be run. A script that was never run
  is not "done".
- If a search returned nothing, say "I found nothing" — do not
  invent a result to fill the gap.
- Keep the failure in the record until it is fixed. A failed
  tool call is not a completed step.

## When to stop and ask

Stop and ask the user when:

- A choice would change the plan or the cost
- You need a credential, a file, or a decision only they can give
- The task touches money, publishing, deleting, or contacting
  someone on their behalf

Do not ask again for a decision they already made for this task.
